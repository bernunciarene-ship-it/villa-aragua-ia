# Checklist AI SEO

Checklist final para revisar qualquer página, artigo, FAQ ou bloco de conteúdo antes de considerá-lo pronto para publicar. Última etapa antes de sair desta skill para publicação.

## As catorze perguntas

- [ ] **Responde uma pergunta real do hóspede?** (ver `consultas-alvo-ai-search.md` — se não responde a nenhuma consulta real, reconsiderar se o conteúdo é necessário)
- [ ] **Tem resposta direta no início?** (primeiro parágrafo/primeira frase, sem enrolação)
- [ ] **Diferencia Pousada e Casa quando necessário?** (nunca generalizar quando a regra é diferente entre os dois produtos)
- [ ] **Usa apenas dados oficiais?** (todo fato vem de `DADOS_OFICIAIS_ATENDIMENTO_VILLA_ARAGUA.md`, do concierge oficial, ou de avaliação real)
- [ ] **Evita promessas perigosas?** (nada de desconto, disponibilidade, exceção operacional ou pacote não validado por `villa-aragua-pricing-revenue`)
- [ ] **Tem FAQ?** (ao menos 3-6 perguntas curtas, no formato de `faq-pousada-casa-bombinhas.md`)
- [ ] **Tem CTA leve para WhatsApp?** (convite, nunca pressão ou urgência falsa)
- [ ] **Tem links internos úteis?** (para o produto irmão, para o guia de região, para a página de reserva direta, conforme aplicável)
- [ ] **Pode ser entendido fora de contexto?** (um parágrafo isolado, lido sem o resto da página, ainda faz sentido?)
- [ ] **Pode ser citado por uma IA sem distorção?** (a resposta direta é precisa o suficiente para não virar uma generalização errada se resumida por terceiros?)
- [ ] **Não inventa preço, disponibilidade, avaliação ou distância?** (checagem final contra qualquer dado não confirmado)
- [ ] **Não promete ranking?** (nenhuma frase do tipo "isso vai aparecer no topo do Google/ChatGPT")
- [ ] **Ajuda uma pessoa real a decidir melhor?** (o teste final de utilidade — se a resposta a essa pergunta for não, o conteúdo não está pronto, independente de estar tecnicamente correto)
- [ ] **Indica qual skill deve executar a próxima etapa?** (copywriting para escrever, humanizer para revisar tom, social-media-manager para adaptar ao Instagram, pricing-revenue para validar valor, sales-receptionist para alinhar resposta de WhatsApp)

## Como aplicar o checklist

- Rodar as catorze perguntas em sequência, marcando cada uma como atendida ou pendente.
- Qualquer "não" nas perguntas de dado/preço/promessa (itens de risco) bloqueia a publicação até corrigir — não são opcionais.
- Qualquer "não" nas perguntas de utilidade/estrutura (resposta direta, FAQ, links internos) é motivo para revisar a estrutura antes de publicar, mas pode ser resolvido com ajuste editorial rápido.
- Se o conteúdo passar em todas, ainda assim marcar explicitamente qual é a próxima skill a acionar — este checklist nunca termina em "conteúdo pronto e esquecido", sempre aponta o próximo passo.


## Como usar este arquivo na prática

1. Rodar este checklist como última etapa antes de qualquer publicação, depois de `estrutura-conteudo-citavel.md` já ter sido aplicado ao conteúdo.
2. Bloquear a publicação enquanto houver "não" em qualquer item de risco (dado inventado, promessa perigosa, promessa de ranking).
3. Registrar o resultado (modelo acima) para manter rastreabilidade do que já foi revisado.
4. Encaminhar para a próxima skill indicada assim que o conteúdo estiver aprovado.
