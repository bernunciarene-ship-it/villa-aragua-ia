# Checklist de dados da campanha

O que pedir ao gestor (Renildo/equipe) antes de fazer qualquer análise. Sem esses dados, a resposta correta é sinalizar a lacuna — nunca preencher com estimativa apresentada como fato.

## Checklist

- [ ] **Período analisado** — datas exatas de início e fim.
- [ ] **Print ou exportação do Meta Ads** — fonte real das métricas (investimento, alcance, impressões, CPM, CTR, CPC, conversas).
- [ ] **Investimento** — valor total gasto no período, e se possível por campanha.
- [ ] **Campanhas** — nome/objetivo de cada campanha ativa no período.
- [ ] **Conjuntos de anúncios** — recorte por público/posicionamento, se disponível.
- [ ] **Anúncios** — quais peças específicas rodaram (copy + criativo).
- [ ] **Leads/conversas** — número de conversas iniciadas no WhatsApp no período, idealmente com origem (campanha/anúncio) quando rastreável.
- [ ] **Reservas confirmadas** — número e valor, separado por produto (Pousada/Casa).
- [ ] **Receita gerada** — separando receita reservada de receita recebida (ver `roas-cpa-cpl-roi.md`).
- [ ] **Produto vendido** — Pousada Arágua ou Casa Arágua, para cada reserva/lead relevante.
- [ ] **Canal de origem** — quando conhecido (Meta Ads, orgânico, WhatsApp direto, Google, Booking, Airbnb, Decolar, hóspede antigo, indicação) — ver `atribuicao-canais.md`.
- [ ] **Custos relevantes** — qualquer custo operacional atribuível que o gestor tenha disponível (limpeza, café, lavanderia), necessário para calcular ROI (não apenas ROAS).
- [ ] **Observações do WhatsApp** — objeções recorrentes, motivo de reservas perdidas, tempo de resposta percebido, qualquer nota qualitativa da equipe que ajude a interpretar os números.

## Como agir quando faltar item do checklist

- Analisar com o que estiver disponível, declarando explicitamente quais itens faltaram e como isso limita a conclusão (ex.: "sem dado de receita recebida, o ROAS abaixo é só sobre receita reservada").
- Nunca interromper a entrega de valor esperando "dado perfeito" — uma análise parcial e honesta sobre suas limitações é mais útil do que nenhuma análise.
- Sempre oferecer, ao final, a lista específica do que ajudaria a próxima análise a ser mais completa.

## Nível mínimo de dado para cada tipo de análise

| Análise desejada | Dado mínimo necessário |
|---|---|
| Ler métricas de topo (`metricas-meta-ads.md`) | Print/exportação com investimento, alcance, impressões, CPM, CTR, CPC do período |
| Analisar funil (`funil-whatsapp-reserva.md`) | Número de leads, respondidos, qualificados, orçamentos, reservas confirmadas/perdidas |
| Calcular CPL/custo por conversa/CPA (`roas-cpa-cpl-roi.md`) | Investimento + número de leads/conversas/reservas |
| Calcular ROAS | Investimento + receita reservada ou recebida (declarando qual) |
| Calcular ROI | Tudo do ROAS + custo operacional atribuível (mesmo que aproximado, mas informado pelo gestor, nunca estimado pela IA) |
| Atribuir canal (`atribuicao-canais.md`) | Origem informada pelo lead ou dado de clique/rastreamento |
| Comparar criativos/públicos (`analise-criativos-publicos.md`) | Métricas por anúncio/conjunto + qualidade de conversa observada |
| Montar relatório (`relatorio-semanal-mensal.md`) | Soma de todos os itens acima, na medida do disponível |
| Recomendar decisão (`decisoes-otimizacao.md`) | Pelo menos funil + métricas de topo de mais de um período, para evitar decisão por ansiedade de curto prazo |

## Como usar este arquivo na prática

1. No início de qualquer pedido de análise, rodar este checklist junto com o usuário.
2. Marcar o que já foi fornecido e o que falta.
3. Seguir com a análise possível, sinalizando as lacunas de forma explícita no relatório final (ver `relatorio-semanal-mensal.md`).
4. Nunca tratar a ausência de dado como convite para estimar — é convite para perguntar ou declarar o limite da análise.
